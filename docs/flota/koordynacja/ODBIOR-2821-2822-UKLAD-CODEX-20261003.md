## Pomiar powiększenia i czytelności

200% ustawiono w prawdziwym `chrome://settings/appearance`, wyborem
„Powiększenie strony: 200%” w tylko własnym profilu przeglądarki.
Nie użyto CSS `zoom`, większej czcionki korzenia ani pinch zoom.

| Pomiar | 320 px | 200% |
|---|---:|---:|
| `innerWidth` / `outerWidth` | 320 / 1280 | 640 / 1280 |
| `devicePixelRatio` | 1 | 2 |
| `visualViewport.scale` / CSS root `zoom` | 1 / 1 | 1 / 1 |
| CDP `cssVisualViewport.zoom` | 1 | 2 |

Są to dwa wymagane warianty: 320 px przy 100% i okno desktopowe
powiększone natywnie do 200%. Nie deklarujemy jednoczesnego 320 px/200%,
ustawienia czcionki przeglądarki 200%, czytnika ekranu ani pełnego audytu WCAG.

Minimum tekstu podstawowego i mierzonego pola: **18 CSS px**; pole nazwy
miało 64 px wysokości. Minimum mierzonego ważnego przycisku/summary:
**50,5 CSS px**, rosnącego po zawinięciu. Brak przewijania całej strony
w bok w 34 pomiarach. Każdy z 30 celów klawiatury miał widoczny właściwy
prostokąt fokusu, którego punkt wewnętrzny trafiał w kontrolkę, nie w
nakładkę. Dla linku wielowierszowego sprawdzono jego `clientRects`,
nie pustą przerwę w środku sumarycznego bounding boxa.

Wtórna metryczka „Ten zeszyt widzą wszyscy” i podpis autora mają 16 px.
To dopuszczony `--text-help`: `docs/design/DESIGN_SYSTEM.md` §2.1,
wiersz 174, wymaga głównego tekstu obok ≥18 px. Widok
`collections/show.blade.php:76` ma obok opis 18 px i tytuł 28 px;
`recipe-card.blade.php:23` ma obok tytuł przepisu. Kontekst i rozmiary
zapisano w metrykach. Nie potraktowano metryczki jak samodzielnej
instrukcji; potwierdzenia, komunikaty sukcesu i błędy mają minimum 18 px.

PNG pochodzą z CDP `Page.captureScreenshot`. Zapis viewportu nie używa
clip; zapis pełny używa DIP z `Page.getLayoutMetrics.contentSize`,
a nie `cssContentSize`. Przy natywnym 200% te wymiary są różne.
Końcowy weryfikator sprawdził fizyczną szerokość każdego pełnego PNG
wobec zapisanych metryk. Ogląd reprezentatywnych obrazów potwierdził
czytelne nazwy, potwierdzenia, sukces oraz polski ekran odmowy 403.

## Próby przygotowania zachowane uczciwie

Historyczne próby nie są końcowym dowodem AC. Zostały zachowane osobno:

- `attempt-1`: helper odczytał profil z cache relacji przed ponownym load;
  przeglądarka nie ruszyła.
- `attempt-2`: helper oczekiwał nieistniejącego meta CSRF; końcowo używa
  rzeczywistego tokenu z wcześniejszego formularza tego członka.
- `attempt-3`: TRUNCATE własnych fixture prawidłowo odmówił przez D-072;
  Laravel CLI zwrócił 0 mimo wyjątku. Stare fixture nie zostało zaliczone.
  Przygotowanie otrzymało twardy exit 1 i jawnie sprawdzaną tożsamość;
  nowy stan utworzono `migrate:fresh` tylko na własnej bazie.
- `attempt-4-functional`: cała macierz funkcjonalna PASS, lecz pełne
  obrazy Playwright przy native zoom 2 miały niepoprawny clip.
  Nie są dowodem wizualnym 200%.
- `attempt-5-helper`: oczekiwanie na przemijającą podpowiedź wyglądu
  zatrzymało helper przed pierwszym scenariuszem.
- `attempt-6-partial`: próbnik środka wielowierszowego linku trafił w LI,
  a zbyt szybkie wejście poprzedziło koniec istniejącego autofocus400ms
  (`resources/js/app.js:1591`). Nie zaliczono tej próby. Końcowy przebieg
  mierzy po zakończeniu ruchu interfejsu, w aktywnej karcie, i sprawdza
  rzeczywisty fokus docelowego pola.

Żadnego ERROR/timeout ani historycznego częściowego wyniku nie uznano
za PASS lub za właściwą kontrolę ujemną aplikacji.
