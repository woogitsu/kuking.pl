### Z5 — WAGA KRYTYCZNA — punkt 5: skrypt regresyjny minutnika czyta `app.js` przez wycinanie tekstu i po refaktorze dostaje kod bez importów

**To jest ustalona, nie zgadnięta przyczyna czerwieni tego PR-a.**

`scripts/minutnik-regresja.mjs` (na `main`, **gałąź go nie rusza**) buduje scenę tak:

```js
const source = readFileSync('resources/js/app.js', 'utf8');
const begin = source.indexOf("document.querySelectorAll('.cook-timer').forEach");
const end   = source.indexOf('// --- Karuzela zdjęć', begin);
...
await page.addScriptTag({ content: source.slice(begin, end) });
```

Wstrzykuje **sam wycinek** `app.js` jako zwykły skrypt, bez modułów.
Na tej gałęzi wycinek to wiersze **360–496**, a arytmetyka minutnika i Wake Lock
przeniosły się do modułów importowanych w wierszach **24–25**, czyli **poza wycinkiem**:

```js
import {pozostaloSekund, formatMinutySekundy, kluczStanu, zapiszStan, odczytajStan} from './minutnik-krok.js';
import {utworzKontrolerWakeLock} from './wake-lock-gotowania.js';
```

Wstrzyknięty wycinek odwołuje się do nazw, których w tej stronie nie ma.
Handler `forEach` przerywa się na `ReferenceError`, więc **nigdy nie dochodzi do
`przycisk.hidden = false`** — a `cook-timer-start` jest w Blade renderowany
z atrybutem `hidden` (wiersz 122). Dokładnie to widać w logu CI:

```
locator.click: Timeout 30000ms exceeded.
  - waiting for locator('.cook-timer').first().locator('.cook-timer-start')
    - locator resolved to <button hidden="" type="button" class="… cook-timer-start">
    - element is not visible
```

Oblane scenariusze — `zwykle_odliczanie_jeden_koniec_restart`, `pauza_przed_terminem`,
`pauza_przez_koniec_jedna_finalizacja`, `niezalezne_minutniki`,
`aktualny_czas_dostepny_bez_spamu_live` — to **komplet pięciu `check(...)`
z `scripts/minutnik-regresja.mjs`** (wiersze 71, 89, 103, 115, 129). Żaden nie jest
testem produktu: wszystkie padły na tej samej, jednej przyczynie technicznej.

**Co to znaczy:** czerwień #913 **nie dowodzi**, że minutnik jest zepsuty dla człowieka
— dowodzi, że przyrząd nie nadąża za kształtem kodu. Ale **nie dowodzi też**, że minutnik
działa: po tej zmianie **nie istnieje żaden przebieg, który by to sprawdził**.
To jest gorsze niż czerwień — to utrata pokrycia.

Sprawdziłem i **wykluczyłem** drugą możliwą przyczynę: regex
`/<div class="cook-timer"[\s\S]*?<\/div>/` nadal łapie cały blok, bo dodany
`cook-timer-anuluj` stoi **przed** pierwszym `</div>` i w bloku nie ma zagnieżdżonego `<div>`.

**Do rozważenia przez autora** (nie polecenie): dostosować `minutnik-regresja.mjs`
do nowego kształtu — np. wstrzykiwać moduły jako `type="module"` albo budować scenę
z `public/build`. `scripts/minutnik-fokus.mjs` czyta `public/build/manifest.json`,
więc taki wzorzec w repozytorium już istnieje.

`_wspolne/skrzynka/zlecenia/`. **Żadne z trzech audytowanych stanowisk nie ma tam pliku.**
Katalog zawiera wyłącznie dziesięć plików `gpt-*`:
`gpt-decyzja-205-i-motyw-370`, `gpt-dziennik-wyjatkow`, `gpt-moja-wersja`, `gpt-ocr-import`,
`gpt-odbior-czy-przygotowanie`, `gpt-pomiar-feedu-i-budzetu`, `gpt-tokeny-zaproszen`,
`gpt-widmo-zamkniec`, `gpt-zamkniecia-607-608-i-inwentarz-ci`, `gpt-zawieszone-konto`.

**Nie zakładam nowych plików w `zlecenia/`** — plik w tym katalogu czyta się jak polecenie,
a to są uwagi doradcze; utworzenie go byłoby zmianą znaczenia, nie zapisem.
Pełne uwagi dla trzech stanowisk stoją wyżej w tym meldunku.
Gdy koordynator wskaże właściwe pliki albo potwierdzi, że mam je założyć
(z nagłówkiem **uwagi audytu, nie polecenie**), dopiszę je w minutę.
